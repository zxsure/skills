# Interactive HTML — Acceptance Criteria & Quantitative Evaluation Rubric

Every `.html` micro-application generated by the `interactive-html` skill is evaluated against **5 Hard Gates (Zero-Tolerance Blockers)** and a **100-Point Craft Rubric**.

To pass acceptance, a generated `.html` artifact **must**:
1. Pass **all 5 Hard Gates (5/5)**, AND
2. Achieve a **Total Craft Score ≥ 85 / 100** when audited by `node skills/interactive-html/scripts/verify-html.mjs <file.html>` (and have zero runtime errors when opened in the preview panel / browser).

---

## Part 1: The 5 Hard Gates (Pass / Fail Blockers)

| Gate ID | Gate Name | Verification Rule | Failure Remediation |
| :--- | :--- | :--- | :--- |
| **HG-1** | **Self-Contained HTML5 Document** | Starts with `<!DOCTYPE html>`, contains inline `<style>` and `<script>`, and is saved inside the project workspace (e.g. `.interactive-html/<slug>.html`, never `/tmp`). | Inline all styles/scripts and write inside `.interactive-html/`. |
| **HG-2** | **Zero JS Syntax or Runtime Errors** | Every `<script>` block compiles cleanly via `new vm.Script()` with zero syntax errors, and produces zero `console.error` or uncaught exceptions on load and interaction. | Fix any syntax typos, undefined DOM IDs, or null reference errors. |
| **HG-3** | **Sandbox & Offline Safety** | Zero `fetch(`, `XMLHttpRequest`, `WebSocket(`, external `<link href="https://fonts.googleapis.com...">`, or unverified external `<script src="...">` calls. | Replace external calls with deterministic in-browser simulation data and system font stacks. |
| **HG-4** | **Multi-Modal Interactivity (`≥ 3` Modalities)** | Must expose **at least 3 distinct interactive input modalities** from the 6 recognized classes:<br/>1. Range sliders (`input[type="range"]`)<br/>2. Live text/number editor inputs (`input[type="text\|number"]`, `<textarea>`, `contenteditable`)<br/>3. Direct 2D canvas/SVG spatial pointer manipulation (`pointerdown`/`pointermove` or clickable SVG `[data-*]` nodes)<br/>4. Tangle-style scrubbable inline prose numbers (`.scrub-num`)<br/>5. Domain action / preset / mode buttons<br/>6. Keyboard shortcuts (`keydown`) | Add direct canvas manipulation, a live custom input box, or Tangle scrubbable inline numbers so the page is not just buttons + sliders. |
| **HG-5** | **Dynamic Visual Stage** | Contains at least one `<canvas>` or `<svg>` visual stage actively rendered/mutated by JavaScript. | Add an interactive `<canvas>` or `<svg>` diagram that visualizes the underlying mechanism. |

## Part 2: The 100-Point Quantitative Craft Rubric (Threshold: `≥ 85 / 100`)

### 1. Interactive Modality & Control Richness (25 points)
- **+12 pts**: Implements at least 3 distinct interactive input modalities.
- **+7 pts**: Implements a 4th distinct modality (e.g., combining sliders + presets + direct canvas drag + live text/number input).
- **+6 pts**: Includes **Tangle-style scrubbable inline prose** (`.scrub-num` draggable numbers inside narrative text) OR **direct 2D pointer dragging** (`pointerdown` + `pointermove` + `setPointerCapture`).

### 2. Motion, Physics & High-DPI Visual Craft (20 points)
- **+8 pts**: Uses continuous 60fps animation (`requestAnimationFrame`), SVG packet/beam motion (`<animateMotion>` / `stroke-dasharray`), or spring physics (`stepSpring` / `F = -kx - cv`).
- **+6 pts**: Uses tactile CSS spring/smooth easing curves (`cubic-bezier(0.34, 1.56, 0.64, 1)` or `--spring`).
- **+6 pts**: Scales all `<canvas>` elements by `window.devicePixelRatio` for crisp Retina rendering (automatically awarded if pure vector `<svg>` is used with `viewBox`).

### 3. End-to-End Causal State Wiring & Real Domain Logic (25 points)
- **+10 pts**: Central reactive state & recomputation pipeline (event listeners mutate state and trigger a central recompute/render flow that updates `≥ 3` distinct DOM/Canvas/SVG regions).
- **+8 pts**: Real in-browser domain calculation (e.g., actual softmax/cosine math, real tree/DAG node splitting/cloning, real particle collision physics, or real tokenization) rather than static string swapping.
- **+7 pts**: Live custom input or direct spatial manipulation dynamically propagates across multiple connected stages/views.

### 4. Bespoke Visual Aesthetic & Layout Responsiveness (15 points)
- **+5 pts**: Uses CSS Custom Properties (`--`) with a cohesive domain-matched palette.
- **+5 pts**: Includes a live 1-click theme switcher (`data-theme` toggle) or bespoke multi-pane/pipeline macro topology.
- **+5 pts**: Includes responsive `@media` breakpoints so split panes/grids adapt cleanly to narrow preview panels.

### 5. Pedagogical Clarity & Live Annotations (15 points)
- **+5 pts**: Clear plain-English intuition hook explaining *why* the mechanism exists.
- **+5 pts**: Dynamic inline annotations, citations, state diffs, or formulas that update live as the user turns knobs.
- **+5 pts**: Diagnostic feedback for edge cases / failure modes (e.g., showing *why* a boundary stampede, split-brain, severed chunk, or starvation bug happens when triggered).

## Part 3: Automated Verification Workflow

Run the automated verifier on a single file or an entire directory of generated explainers:

```bash
# Verify a single generated interactive HTML file:
node skills/interactive-html/scripts/verify-html.mjs .interactive-html/<topic-slug>.html

# Verify all generated HTML files in .interactive-html/ and check topology diversity:
node skills/interactive-html/scripts/verify-html.mjs .interactive-html
```

- **Exit code `0`**: All Hard Gates passed and Craft Score `>= 85/100`.
- **Exit code `1`**: One or more Hard Gates failed or Craft Score `< 85/100`. The script outputs specific actionable items to fix before calling `preview`.
